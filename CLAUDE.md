## Project Overview

apis.is is a collection of Icelandic-specific public APIs written in
TypeScript. It cleans up and serves data from Icelandic sources (scraped pages,
XML feeds, undocumented APIs) as JSON, plus community-maintained meetup data.
Deployed on **Cloudflare Workers**; `/` lists the endpoints, and serves an
explorer page to browsers.

## Commands

```bash
# Install dependencies
npm install

# Type check (regenerates worker-configuration.d.ts first)
npm run typecheck

# Lint and format (Biome)
npm run lint            # check only
npm run format          # auto-fix

# Run all unit tests (in workerd, the Workers runtime)
npm test

# Run a single test file
npx vitest run src/endpoints/gengi.test.ts

# Run locally in the Workers runtime
npm run dev

# Coverage (branch: 85%, line: 95% thresholds, enforced by vitest.config.ts)
npm run test:coverage
```

## Architecture

**Request flow:** default-exported `fetch` handler → Router (URLPattern-based) →
Endpoint handler → Response. Requests are logged by Workers observability.

- `src/index.ts` — Entry point, registers routes and exports the `fetch`
  handler. Wrangler bundles it directly. Code runs on Cloudflare Workers, so it
  must stick to web-standard APIs and `nodejs_compat` (no runtime WASM
  compilation).
- `worker-configuration.d.ts` — Workers runtime and `Env` types, generated by
  `wrangler types` on `npm install` and `npm run typecheck`. Not committed, so
  wrangler updates don't leave it stale.
- `src/router.ts` — Custom router using native `URLPattern` API, supports path
  params (e.g., `/x/car/{number}?`)
- `src/error-monitor.ts` — Auto-creates GitHub issues for uncaught errors in
  production (deduplicates via fingerprinting)
- `src/endpoints/` — One file per API endpoint, registered in `src/index.ts`
- `src/data/meetups.json` — Static meetup data (community-maintained via GitHub
  issues + automated workflow)
- `src/explorer.ts` — HTML API explorer that `/` serves to browsers
  (`Accept: text/html`); API clients still get the JSON endpoint list
- `src/rss.ts` — RSS 2.0 feed generator used by meetups endpoint
- `src/cache.ts` — `withCache(key, ttlSeconds, fetcher)` in-memory cache for
  upstream data (per isolate); pair with `cacheControl(ttl)` for the
  `Cache-Control` header
- `src/health.ts` — Hourly Cron Trigger (`scheduled` handler) that runs each
  endpoint's `health` check and opens/closes `endpoint-down` issues. New
  endpoints should set `handler.health` with a Zod `schema` for a healthy
  response (see `gengi.ts`); tests validate mocked responses against it.
- `scripts/remap-stack.ts` — Source-maps stack traces in error issues; run by
  `.github/workflows/remap-error-trace.yml`

## Adding Endpoints

Only add an endpoint when it adds something the upstream doesn't already
offer. Check for an official API first (e.g. https://api.vedur.is/ lists
Veðurstofa's). Worth wrapping:

- Data with no API (scraped pages, dashboards, embedded JS)
- An awkward upstream format: XML, CAP, Icelandic-only field names, no CORS
- Combining several sources into one response
- Caching an upstream that rate-limits or is slow

If the upstream already serves clean JSON with CORS, link to it instead of
wrapping it, and say so on the endpoint's issue. Real-time data that isn't
available anywhere else is the most valuable.

## Code Quality Requirements

- TypeScript strict mode
- All changes must pass: `npm run lint`, `npm run typecheck`, `npm test`
- New features/fixes require tests
- Coverage thresholds enforced in CI: 85% branch, 95% line
- **Always verify coverage** after writing or modifying tests by running the
  coverage commands above. CI will fail if thresholds are not met.
